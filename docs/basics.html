AI Engineering · Before the token economy

The Basics Under the Bill

A coding agent's bill is not a mystery and not a flat fee. It is a handful of simple ideas multiplied together: a model that remembers nothing, text counted in tokens, a conversation sent again on every call, a cache that makes the repeat cheap, and instructions and helpers that ride along. This page builds those ideas one at a time, on one small task you can trace by hand, with every number measured.

The big picture

One picture, then the parts

Every diagram on this page uses the same marks, so learn them once:

The 60-second answer

  • The model remembers nothing. To take one more step, the harness re-sends everything: instructions, tools, CLAUDE.md, every file read and every command output so far.
  • You pay per token, per call. A token is a piece of a word (English averages 3.8 characters a token, code 2.5). Output costs 5× input.
  • The cache makes repeats cheap. Text sent seconds ago is read back at 0.05× the input price on Sonnet 5.5. After a pause longer than the cache's lifetime it is written again at full price.
  • Before you type, the context is already 20.2K tokens (Claude Code's own instructions and tools), and 29.5K with plugins and skills installed. CLAUDE.md rides on top of that, on every call.
  • A subagent is a fresh, small context that does a side job and returns a short report, so the lead's context doesn't grow. It saves money only when that side job is big.
1 · The model

A function that predicts the next token

A large language model (LLM) is a very large function. You give it text; it returns its best guess at the next small piece of text. To write a sentence it runs again and again, each time with the text so far plus the piece it just added. That repeat-until-done is called generation.

Two facts about it set the whole bill:

  • It is stateless. Between calls it keeps nothing: no memory of you, your repo or the last answer. Whatever it should know has to be in the text you send this time.
  • Reading is cheaper than writing. The text you send is processed in one parallel pass. Each token it writes back needs its own pass. That is why output is priced at 5× input.
The toy for the whole page

A tiny repo: shop/cart.py has a bug (the cart total ignores quantity), tests/test_cart.py catches it, and a 13-line CLAUDE.md says how to run the tests. We ask Claude Code: "The test fails. Find out why and fix it." It is in this repo under docs/basics/toy/; docs/basics/measure.py runs it.

2 · Tokens

Text is counted in tokens

The model doesn't see letters or words. A tokenizer cuts text into tokens: common words are one token, rare words and code split into several pieces. Every limit and every price is in tokens.

Rule of thumb from these numbers: a page of English prose (about 3,000 characters) is roughly 800 tokens; the same length of code is closer to 1,200.

3 · One call

Every call sends everything again

An API call is one request to the model. It carries three things, in this order: the tool definitions (what the model may ask to run), the system prompt (standing instructions), and the messages (the conversation so far, including every tool result). The reply comes back with four counts, and these four numbers are the whole bill:

input_tokenscache_read_input_tokenscache_creation_input_tokensoutput_tokens

Because the model is stateless, the second call contains the first call's text, plus the reply, plus the tool result. The toy task took 3 calls:

The context window is the most a single call can hold. When a long session approaches it, the harness compacts: it replaces the history with a written summary, and the next call starts from that smaller context.

4 · The price list

Four prices per model

Each token in a call is charged one of four rates. Input: sent and not cached. Cache write: sent and stored for reuse (at 1.25× input for a 5-minute lifetime, 2× for 1 hour). Cache read: re-sent and found in the cache. Output: written by the model, thinking included.

Fable 5.1$10.00$12.50$20.00$0.25$50.00
  • Output is 5× input on every model above. Long answers and long thinking are the expensive kind of token.
  • A cache read is 0.05× input on Opus 5.5 and Sonnet 5.5, 0.1× on Haiku 5.5 and 0.025× on Fable 5.1. Reading 100,000 cached tokens on Sonnet costs $0.01; writing them costs $0.25 to $0.40.
  • Haiku 5.5 has a size step. Once a single request passes 100,000 tokens, every Haiku rate is 5× (input $0.50 instead of $0.10).
  • Fast mode doubles every Opus rate. It is the same model at higher speed: $8 / $40 per million on Opus 5.5 instead of $4 / $20, with the cache multipliers on top. On a Claude subscription it is paid from usage credits, not the plan, even when plan usage is left. Once turned on with /fast it carries into new sessions, and turning it on mid-session writes the whole conversation again at the fast uncached price.
  • US-only inference (data residency) adds 10% to every rate, and web search adds $10 per 1,000 searches on top of the tokens it brings in.
  • Codex is billed in credits with a cheaper rate for cached input and no separate charge for writing the cache. Its Fast mode costs 2× credits (2.5× of included plan usage) and Ultrafast 6× (8×). The ideas on this page carry over; the numbers differ.
  • On a subscription you don't see per-token bills, but usage is counted in the same tokens; tools like tke price them at these list rates so sessions can be compared.
5 · The prompt cache

The repeat is cheap, if it is recent and identical

Since every call re-sends the same beginning, Anthropic keeps recently processed prompts in a prompt cache on its servers. On the next call, the longest identical prefix (the same text from the very first character) is read from the cache at the read price. Everything after the first difference is processed and written again.

  • Measured: the very first call of a fresh session read 16,868 tokens from the cache and wrote 3,355. Claude Code's system prompt had been cached by earlier sessions on the same account. Run again straight away, the same call read 20,223 and wrote nothing.
  • Lifetime: 5 minutes by default, refreshed every time the entry is used; 1 hour costs more to write. Claude Code on a subscription uses 1 hour for the main conversation and 5 minutes for subagents; with an API key or usage credits, 5 minutes unless you set promptCacheTtl.
  • Scope: caches are shared within your organisation (and workspace), never across organisations, and only for prompts of at least 512 tokens on current models.
  • Switching models mid-session misses the cache: each model has its own.
6 · The agent

A model, some tools, and a loop

An agent is a model that can act. The harness gives it tools (read a file, edit a file, run a shell command, search) and runs a simple loop: call the model; if it asks for a tool, run it, append the result, call again; if it just replies, stop.

That is why agents cost far more than chat: a task that takes 60 turns re-sends its growing context 60 times.

7 · What fills the context

Startup context, CLAUDE.md and the rest

Before the agent reads a single file, the first call already carries the harness's system prompt and the definitions of every tool, plus anything you've installed that adds to them.

CLAUDE.md: standing instructions you write

CLAUDE.md is a plain Markdown file of instructions (how to run the tests, the rules of the codebase). Claude Code reads it at the start of every session and puts it in the context, so it rides along on every call, read from the cache.

  • Keep it under about 200 lines. Anthropic's advice: longer files take more context and are followed less reliably. Move rules that apply to one part of the code into .claude/rules/ with a path, so they load only there.
  • Imports don't save anything. @path/to/file pulls a file in at launch, so it costs the same as pasting it.
  • HTML comments are free. <!-- notes for humans --> are stripped before the file reaches the model.
  • The per-call cost is small, the attention cost isn't. Read from the cache, the toy's 355-token CLAUDE.md costs $0.07 per thousand Opus calls. The real reasons to keep it short are adherence and the full re-write after every cache rebuild.

After startup, the context fills with the work itself: your messages, the model's replies and tool calls, and above all tool results: the files it read and the command output it saw. A single unfiltered test log or a whole large file can outweigh everything else, and it is then re-read on every later call.

The formula, now with every part named

cost of a call = tokens read from cache × read price + new tokens × write price + output tokens × output price. A session is that, summed over every call. Everything else on this page is about making one of those terms smaller.

10 · Subagents

A fresh, small context for a side job

A subagent is a second agent the lead starts for one job. It gets a fresh context: its own short system prompt (not Claude Code's), your CLAUDE.md files, and a brief the lead writes. It can run on a different model. When it finishes, only its report comes back into the lead's context; the files it read and the output it saw stay with it.

  • On this tiny task it didn't save: $0.033 in total against $0.031 without it (9% more), because the lead still paid for writing the brief and reading the report, and the job was only two small files.
  • It saves when the side job is big: a search through many files or a long log, done on a cheaper model, while the lead's context stays small for every later call.
  • The model is set per subagent. A model: line in its file wins; otherwise it uses the lead's model (or CLAUDE_CODE_SUBAGENT_MODEL). The built-in Explore agent runs on the main conversation's model, so a search on an Opus session is billed at Opus rates.

Common confusions

Eight things that sound right and aren't

"The model remembers our conversation."It remembers nothing. The harness keeps the conversation and re-sends all of it on every call; that repeat is most of the bill.
"The prompt cache is on my laptop."It is on the provider's servers, per organisation, and lasts minutes. What's on your laptop are transcripts and settings.
"A token is a word."English averages 1.47 tokens per word here, and code packs fewer characters into each token than prose.
"A long CLAUDE.md costs a fortune on every call."Cached, it is cheap per call. The real costs are weaker adherence and the full re-write after every rebuild or edit.
"Switching to a cheaper model halfway saves money."The new model has a cold cache, so the whole history is written again at its write price. Choose the model when you start.
"Fast mode is just a nicer setting."It doubles every Opus rate, is paid from usage credits even when plan usage is left, and stays on for new sessions until you turn it off.
"Subagents always save tokens."On the toy, the subagent version cost 9% more. They pay off for big side jobs on cheaper models.
"Output is a small part of the bill."Output is 5× the input price, and thinking counts as output.
Do it

Three questions to check yourself

  1. The toy's CLAUDE.md was 13 lines and 355 tokens, about 27 tokens a line. Roughly what does a 400-line CLAUDE.md cost over a 200-call Opus 5.5 session with a 1-hour cache?

    Show the answer

    About 10,900 tokens. Written once: $0.087. Read 200 times: $0.44. Total about $0.52. Cheap per session, but it is attention spent on every call, and it is written again after every rebuild.

  2. Your Sonnet 5.5 session holds 150,000 tokens and the cache lasts 5 minutes. You take a 20-minute break. What does the next call cost to send its context, compared with sending it warm?

    Show the answer

    Cold: 150,000 × $2.50 per million = $0.375. Warm: 150,000 × $0.10 per million = $0.015. The break makes that one call 25× more expensive to send.

  3. Why did the subagent not save money on the toy, and what kind of job would change that?

    Show the answer

    The job was two small files. The lead still paid to write the brief and read the report, and its own context hardly grew. A subagent pays when its job would otherwise put a lot of text in the lead's context (wide searches, long logs), and when it can run on a cheaper model.

Say it

The two-minute explanation

To a colleague

"A coding agent is a model in a loop. The model remembers nothing, so on every turn the tool re-sends the whole conversation: its own instructions, our CLAUDE.md, every file it has read. We pay per token: cheap for text the cache has seen in the last few minutes, more for new text, five times more for what the model writes. So the bill grows with how big the context gets and how many turns we take. Short sessions, short CLAUDE.md, no long pauses, the cheapest model that does the job, and subagents for big side searches keep it down."
